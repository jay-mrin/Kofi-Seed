# Strict Instructions for This Project

These instructions apply to every task and every session in this project. Read and follow them before inspecting, changing, testing, deploying, or documenting the site.

1. **Keep SuperAdmin data strictly inside the SuperAdmin portal.** Never use, display, expose, aggregate, copy, or share SuperAdmin data on any public page, in the Admin portal, or in any future portal. Do not use SuperAdmin data indirectly in public counters, totals, feeds, reports, or other derived information.
   **User-authorized exception (4 November 2026):** The authenticated AnshuPortal and Badal Portal may each show only the name, amount, email, and order date of successful PayPal orders placed on or after 4 November 2026 at 00:00 Asia/Kolkata that carry that portal's own social-source tag. This includes tagged Admin-route (`standard`) and SuperAdmin PayPal orders. Earlier and untagged orders remain excluded, and existing portals' history stays unchanged. Neither portal may read the other's records or any other SuperAdmin data.
   **User-authorized prospective restriction (10 November 2026, 21:30:40 Asia/Kolkata / 16:00:40 UTC):** Orders created at or after this fixed timestamp for $55 or more must never appear in AnshuPortal or Badal Portal, even if assigned or verified manually. Earlier orders and assignments must remain unchanged. This replaces the manual-verification exception for future high-value orders only.

   **User-authorized Rohit Portal (12 November 2026):** The authenticated Rohit Portal may show only the name, amount, email, and order date of its own successful PayPal orders tagged `rohit` through `/garden`, under the same social-portal scope as Anshu and Badal. Only orders below $55 are eligible; orders of $55 or more remain exclusively in SuperAdmin, including manual assignments. Rohit receives no access to other portals' records or other SuperAdmin data. Existing orders and portal history remain unchanged.

   **Rollout safeguard (12 November 2026):** The production migrations `202611100001`–`202611100003` are pending and contain updates to existing assignments. Automatic approval review rejected applying those historical data updates during Rohit setup. Leave them pending unless separately authorized. 2. **Do not run checks on custom URLs.** Do not open, fetch, probe, validate, crawl, or run automated checks against any custom URL provided for this project, especially payment links. AI initiated requests to these URLs can cause them to misbehave or stop working. Treat such URLs as opaque values unless the user explicitly gives a new instruction for a specific URL.

3. **Preserve all order history and order data.** Never delete order history unless the user explicitly instructs you to do so. Do not make direct or indirect changes that could corrupt, overwrite, misroute, duplicate, hide, or otherwise disturb order records or their relationships. Before any authorized change that could affect order data, identify the impact and use a safe approach that preserves existing records.

If a requested task conflicts with one of these instructions, stop the conflicting action and ask the user for a specific instruction before proceeding. Continue any unaffected work.
